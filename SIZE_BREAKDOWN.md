## 3. Cut plan, ranked by real savings

### ✅ CUT 1 — Embedded .mp4 cutscene media: **≈216.7 MB** (10.9%) — *highest confidence*

**This is dead weight in the web build.**

* `packed-cinematics_assets_all` is 218.80 MB of `.resource` node
  (`CAB-a6c1874f3d6312865d7ffaeaa121573b.resource`) + a 0.02 MB CAB holding the
  26 `VideoClip` stubs (234 bytes each), 17 `AudioClip`s and 26 MonoBehaviours.
* The `VideoClip` assets say `m_OriginalPath = Assets/VideoClip/<name>.mp4`
  and point their media at the `.resource` node.
* But the game code (recovered from `Build/w-pt.data.unityweb`) contains a
  class **`CinematicStreamingAssets`** with
  `ShouldUseStreamingAssetsVideo`, `BuildStreamingAssetsUrl`,
  `GetEmbeddedVideoClip`, `ResolveBaseName`, plus the literal error string
  **"Expected web video clip in StreamingAssets at:"**.
  → On WebGL the game plays `StreamingAssets/VideoClip/<name>.webm`, **never**
  the embedded .mp4. The .mp4 is only the desktop/console fallback.

**How to cut it:** rebuild `packed-cinematics_assets_all` with an empty
`.resource` node (keep the CAB so the 26 `VideoClip` objects and the 17
cutscene `AudioClip`s still resolve, and the fallback path doesn't NRE).
216.77 MB → **≈0.06 MB**.

**Bonus — apply your "1-second black square" idea here too:** replace the
26 files in `StreamingAssets/VideoClip/` with 1-second black `.webm`
→ 54.89 MB → **≈0.1 MB** (this one is outside the 1986.6 figure but is still
downloaded on first play).

> Total from cutscenes: **≈271 MB**

### ❌ NOT worth doing — re-compressing the ZIP

Measured, not guessed:

| Bundle | ZIP (deflate) | zstd-9 | zstd-15 | zstd-19 |
|---|---:|---:|---:|---:|
| `packed-sprites-ui` (112.33 MB raw) | 14.99 MB | 13.63 MB | 13.30 MB | **12.12 MB** (81%) |
| `packed-audio-sfx` (95.46 MB raw) | 95.31 MB | 95.42 MB | 95.39 MB | 95.05 MB (100%) |

zstd only helps the already-compressible bundles and does nothing for the
audio (already OGG). Extrapolating: **≈20–30 MB total** for a full re-zip
with zstd-19, and it breaks the plain-ZIP streaming loader. **Skip it.**

## 5. How to rebuild after a cut

`WebGL.zip` is a plain ZIP whose entries are the 21 Unity bundles. To change
one:

```bash
# 1. split the 100 parts back into one archive
cat StreamingAssets/aa/WebGL.zip.part* > /tmp/WebGL.zip

# 2. replace the bundle you edited
zip -9 /tmp/WebGL.zip new/packed-cinematics_assets_all_*.bundle

# 3. re-split into 100 equal parts and update index.html
#    (aa.partBytes / aa.total) -- 99 x 20 866 662 + remainder
```

`index.html` hard-codes the part sizes:

```js
aa: { partBytes: new Array(99).fill(PART).concat([17340100]),
      total: 2083139638 }
```

and `PART` / `DATA_MB` / the "First run downloads ~1986 MB" copy in the
progress screen must be updated to match, otherwise the resume/checksum logic
desynchronises.

## 6. Reproducing this analysis

`tools/` contains the scripts used (all read-only; they never modify the repo):

| Script | Purpose |
|---|---|
| `tools/tools_zip_audit.py` | Walks the split-archive central directory without materialising the 2 GB zip → per-bundle compressed/uncompressed sizes |
| `tools/tools_analyze.py` | Per-bundle object dump (type breakdown, per-folder rollup, audio clip sizes) via UnityPy |
| `tools/tools_bigbundle.py` | Low-memory bundle reader (mmap + streaming) — required for the 334 MB collections bundle, which OOMs UnityPy |
| `tools/tools_scene_walk.py` | Hand-rolled UnityFS/SerializedFile walker → per-scene sizes, per-scene type breakdown, scene-name recovery |

```bash
python3 -m venv /tmp/venv && /tmp/venv/bin/pip install UnityPy zstandard
python3 tools/tools_zip_audit.py
/tmp/venv/bin/python tools/tools_analyze.py <bundle-file> out.json
/tmp/venv/bin/python tools/tools_bigbundle.py <bundle-file> out.json
/tmp/venv/bin/python tools/tools_scene_walk.py <scenes-bundle> out.json
```

`tools/tools_scene_walk.py` recovers scene names by harvesting the 574-entry
`Assets/Scenes/Hornet/*.unity` path table embedded in the first node of the
scenes bundle and then matching basenames against each scene CAB
(554/574 resolved unambiguously).

### Why not under 1000 MB

The four approved cuts remove everything that is not gameplay. What is left is
the game itself:

| Remaining | MB | Can it be cut? |
|---|---:|---|
| scenes (574 levels) | 328.0 | only by deleting areas |
| sprite atlases (scenery/hero/boss/enemy/UI/effects) | 292.1 | gameplay art |
| animation atlases | 265.1 | gameplay art |
| prefabs | 125.1 | gameplay objects |
| audio (re-encoded) | 172.8 | already at 32–48 kbps |
| collections (placeholders) | 20.3 | already minimal |
| fonts (Latin only) | 10.3 | already minimal |
| cinematics | 4.9 | already minimal |

Getting below 1000 MB needs one more decision: dropping the scenes bundle
(−328 MB) reaches **≈910 MB**, but it removes level content. Alternatively
re-importing every sprite atlas at ASTC/ETC2 + Crunch would take ~300 MB out
without deleting anything, but that requires a Unity project, not file surgery.

  fonts 155, sfx 4 549, hornetvoices 4 456, music 181, voices 1 195).
* Per-bundle re-read with UnityPy after every cut: all AudioClips resolve to
